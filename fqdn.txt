Fully Qualified Domain Name is a complete, unambiguous domain name that specifies the exact location of a network resource, such as a server or website, within the Domain Name System hierarchy.
It is some times called absolute domain name.
The "fully qualified" part means it include every level of the DNS domain hierarchy from the host name all the way to top-level domain and implied root-zone.
>>hostname -f 
FQDN structure : A FQDN is typically written as a list of domain labels seprate by dots, following a hierarchy structure read from right to left.
[hostname].[subdomain(optional)].[second-level domain].[top-level domain].[root]

The structure typically looks like : 
[hostname].[domain name].[TLD]
* mail.google.com : is a mailing server
* www.google.com : web server
* server1.localdomain.net : internal server

** FQDN Importance :
FQDN are fundamental for internet infrastructure and server critical functions:
i) DNS resolution : they allow DNS to reliably translate the human-readable computer to locate each other.
ii) Unique identification : An FQDN provides an unambiguous address, ensuring that every resource (server, device, service) is uniquely identified across entire internet. 
iii) Security-FQDN are essential for issuing SSL/TLS certificates, which bind the certificate to specific, unique FQDN to secure communication. 
iv) Email routing : Mail server require FQDN's for correct email addressing and routing.

A Record (When to use)
i) You are setting up the root/apex domain
ii) you need to point directly to a server's IPv4
iii) you are setting up other critical records like MX (Mail Exchange) records, which often must point to an A Record not CNAME.

CNAME (When to use)
i) you want multiple subdomains (eg www, blog, store) to point to same destination domain)
ii) you are pointing to an external service (like a CDN or a third party host) that might change it's IP address and you want to avoid manual updates.
